# SPEC-FE-004: 인수 기준

## 1. 기능 인수 기준

### 1.1 이미지 업로드 (EVENT-001)

**시나리오 1: 성공적인 업로드**
```
GIVEN 사용자가 대시보드 페이지에 있을 때
AND 유효한 JPG 이미지 파일 (5MB)이 준비되어 있을 때
WHEN 사용자가 이미지를 드래그 앤 드롭 영역에 놓을 때
THEN 파일이 즉시 수신되어야 한다
AND 파일명이 표시되어야 한다
AND "업로드" 버튼이 활성화되어야 한다

WHEN 사용자가 "업로드" 버튼을 클릭할 때
THEN 업로드 진행률이 표시되어야 한다 (0% → 100%)
AND "OCR 처리 중..." 메시지가 표시되어야 한다
AND 버튼이 비활성화되어야 한다

WHEN OCR 처리가 완료되면
THEN 성공 메시지가 표시되어야 한다
AND 추출된 데이터가 미리보기로 표시되어야 한다
AND 기록 리스트가 갱신되어야 한다
AND 차트 데이터가 갱신되어야 있다
```

**시나리오 2: 파일 형식 오류**
```
GIVEN 사용자가 대시보드 페이지에 있을 때
WHEN 사용자가 PDF 파일을 드래그 앤 드롭할 때
THEN 파일이 거부되어야 한다
AND "지원되지 않는 파일 형식입니다" 오류가 표시되어야 한다
```

**시나리오 3: 파일 크기 오류**
```
GIVEN 사용자가 대시보드 페이지에 있을 때
WHEN 사용자가 15MB 이미지 파일을 드래그 앤 드롭할 때
THEN 파일이 거부되어야 한다
AND "파일 크기가 10MB를 초과합니다" 오류가 표시되어야 한다
```

### 1.2 기록 목록 조회 (EVENT-002)

**시나리오 1: 기록 목록 표시**
```
GIVEN 사용자가 25개의 측정 기록을 가지고 있을 때
WHEN 사용자가 대시보드 페이지에 접속할 때
THEN 최신순으로 정렬된 10개의 기록이 표시되어야 한다
AND 페이지네이션이 표시되어야 있다 (1 / 3 페이지)
AND 각 기록이 카드 형태로 표시되어야 한다
```

**시나리오 2: 페이지네이션**
```
GIVEN 사용자가 1페이지에 있을 때
WHEN 사용자가 "다음 페이지" 버튼을 클릭할 때
THEN 2페이지의 10개 기록이 표시되어야 한다
AND URL이 ?page=2로 업데이트되어야 한다
```

**시나리오 3: 날짜 필터링**
```
GIVEN 사용자가 1년간의 기록을 가지고 있을 때
WHEN 사용자가 시작일을 "2025-01-01"로 설정할 때
AND 종료일을 "2025-03-31"로 설정할 때
THEN 해당 기간의 기록만 표시되어야 한다
```

### 1.3 단일 기록 상세 보기 (EVENT-003)

**시나리오 1: 상세 보기 열기**
```
GIVEN 사용자가 기록 목록을 보고 있을 때
WHEN 사용자가 특정 기록 카드를 클릭할 때
THEN 모달이 열려야 한다
AND 전체 체성분 데이터 (20개 필드)가 표시되어야 한다
AND OCR 신뢰도 점수가 표시되어야 있다
AND 측정 일시가 표시되어야 있다
```

**시나리오 2: OCR 원문 토글**
```
GIVEN 상세 보기 모달이 열려 있을 때
WHEN 사용자가 "OCR 원문 보기" 토글을 클릭할 때
THEN OCR로 추출된 원문 텍스트가 표시되어야 한다
```

**시나리오 3: 기록 삭제**
```
GIVEN 상세 보기 모달이 열려 있을 때
WHEN 사용자가 "삭제" 버튼을 클릭할 때
THEN 확인 대화상자가 표시되어야 한다

WHEN 사용자가 "확인"을 클릭할 때
THEN 삭제 API가 호출되어야 한다
AND 모달이 닫혀야 한다
AND 목록에서 해당 기록이 제거되어야 한다
AND 성공 메시지가 표시되어야 한다
```

### 1.4 차트 시각화 (EVENT-004)

**시나리오 1: 체중 변화 차트**
```
GIVEN 사용자가 10개의 측정 기록을 가지고 있을 때
WHEN 사용자가 "체중" 탭을 클릭할 때
THEN 체중 변화 선 그래프가 표시되어야 한다
AND X축은 날짜, Y축은 체중(kg)이어야 한다
AND 각 데이터 포인트가 점으로 표시되어야 한다
```

**시나리오 2: 체성분 변화 차트**
```
GIVEN 사용자가 10개의 측정 기록을 가지고 있을 때
WHEN 사용자가 "체성분" 탭을 클릭할 때
THEN 체지방율, 근육량, 골격근량의 3개 선이 표시되어야 한다
AND 범례가 표시되어야 한다
AND 각 선이 다른 색상이어야 한다
```

**시나리오 3: 신체 점수 차트**
```
GIVEN 사용자가 10개의 측정 기록을 가지고 있을 때
WHEN 사용자가 "신체 점수" 탭을 클릭할 때
THEN 신체 점수 막대 그래프가 표시되어야 한다
AND 각 막대에 점수 레이블이 있어야 한다
```

## 2. UI/UX 인수 기준

### 2.1 반응형 디자인

**데스크톱 (1280px+)**
```
THEN 업로드 섹션과 차트가 2열로 표시되어야 한다
AND 기록 리스트가 전체 너비를 차지해야 한다
```

**태블릿 (768px - 1279px)**
```
THEN 모든 섹션이 수직으로 정렬되어야 한다
AND 차트가 가로 스크롤 없이 표시되어야 한다
```

**모바일 (< 768px)**
```
THEN 카드 기반 레이아웃이어야 한다
AND 차트의 X축 레이블이 겹치지 않아야 한다
AND 터치 타겟이 최소 44px이어야 한다
```

### 2.2 로딩 상태 (STATE-002)

**목록 로딩**
```
THEN 스켈레톤 로딩 UI가 표시되어야 한다
AND 최소 3개의 스켈레톤 카드가 표시되어야 한다
AND 펄스 애니메이션이 적용되어야 한다
```

**차트 로딩**
```
THEN 스피너가 표시되어야 한다
AND "차트 로딩 중..." 메시지가 표시되어야 한다
```

### 2.3 빈 상태 (STATE-003)

**빈 기록 목록**
```
THEN "아직 측정 기록이 없습니다" 메시지가 표시되어야 한다
AND 일러스트레이션 아이콘이 표시되어야 한다
AND "첫 업로드하기" CTA 버튼이 표시되어야 한다
```

### 2.4 접근성

**키보드 내비게이션**
```
GIVEN 사용자가 키보드만 사용할 때
WHEN Tab 키를 누를 때
THEN 포커스가 시각적으로 명확해야 한다
AND 포커스 순서가 논리적이어야 한다
```

**스크린 리더**
```
THEN 모든 이미지에 alt 텍스트가 있어야 한다
AND 모든 버튼에 접근 가능한 이름이 있어야 한다
AND 폼 입력에 레이블이 연결되어야 있다
```

**색상 대비**
```
THEN 텍스트와 배경의 대비비가 최소 4.5:1이어야 한다
AND 대화형 요소의 대비비가 최소 3:1이어야 한다
```

## 3. 성능 인수 기준

### 3.1 로딩 시간

**초기 페이지 로드**
```
THEN First Contentful Paint (FCP)가 1.5초 이내여야 한다
AND Largest Contentful Paint (LCP)가 2.5초 이내여야 한다
```

**상호작용**
```
THEN First Input Delay (FID)가 100ms 이내여야 한다
AND Time to Interactive (TTI)가 3.5초 이내여야 한다
```

### 3.2 업로드 성능

**파일 업로드**
```
GIVEN 5MB JPG 이미지일 때
THEN 업로드가 10초 이내에 완료되어야 한다
AND 진행률이 실시간으로 업데이트되어야 한다
```

**OCR 처리**
```
THEN OCR 처리가 30초 이내에 완료되어야 한다
AND 타임아웃 시 적절한 에러 메시지가 표시되어야 한다
```

## 4. 보안 인수 기준

### 4.1 파일 검증

**클라이언트 사이드**
```
THEN 파일 형식이 magic bytes로 검증되어야 한다
AND 파일 크기가 클라이언트에서 제한되어야 있다
```

**서버 사이드**
```
THEN 서버에서 추가 파일 검증이 수행되어야 있다
AND 악성 파일이 차단되어야 한다
```

### 4.2 인증

```
THEN 모든 API 요청에 인증 토큰이 포함되어야 한다
AND 미인증 사용자는 로그인 페이지로 리다이렉트되어야 한다
```

## 6. 테스트 커버리지

### 단위 테스트
```
THEN 최소 80% 코드 커버리지를 달성해야 한다
AND 모든 컴포넌트에 테스트가 있어야 한다
AND 모든 훅에 테스트가 있어야 한다
```

### 통합 테스트
```
THEN 모든 API 연동이 테스트되어야 한다
AND 주요 사용자 시나리오가 커버되어야 한다
```

### E2E 테스트
```
THEN 업로드 전체 플로우가 테스트되어야 한다
AND 기록 조회 및 삭제 플로우가 테스트되어야 한다
AND 차트 시각화가 테스트되어야 한다
```

### 중간 (P2)
- 우회 방법이 있음
- 간헐적으로 발생

### 낮음 (P3)
- 사소한 UI 문제
- 사용자 경험에 미치는 영향이 적음
