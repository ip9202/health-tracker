# SPEC-FE-004: InBody 데이터 관리 대시보드

## 1. 개요

### 1.1 목적
사용자가 InBody 체성분 데이터를 쉽게 업로드하고, 시각적으로 확인하며,历史 기록을 관리할 수 있는 프론트엔드 UI를 구현합니다.

### 1.2 범위
- 이미지 업로드 UI (드래그 앤 드롭, 진행률 표시)
- 측정 기록 리스트 (페이지네이션, 필터링)
- 데이터 시각화 차트 (체성분 변화, BMI, 신체 점수)
- 단일 레코드 상세 보기

### 1.3 의존 SPEC
- SPEC-DATA-003: InBody OCR 데이터 추출 시스템 (백엔드 API)

## 2. EARS 요구사항

### 2.1 Ubiquitous Language (보편 언어)

**WHEN** 사용자가 대시보드에 접근 **THEN** 시스템은 다음 용어를 사용해야 한다:
- **측정 기록**: 단일 InBody 측정 결과 데이터
- **신체 점수**: InBody 기기가 계산한 종합 신체 평가 점수 (0-100)
- **체지방율**: 전체 체중 중 지방이 차지하는 비율 (%)
- **골격근량**: 골격근의 질량 (kg)
- **BMI**: 체질량 지수 (Body Mass Index)
- **SMI**: 골격근 지수 (Skeletal Muscle Index)

### 2.2 Event-Driven Requirements (이벤트 기반)

**EVENT-001**: **WHEN** 사용자가 이미지를 드래그 앤 드롭으로 업로드 **THEN** 시스템은 다음을 수행해야 한다:
- 파일 유효성 검증 (JPG/PNG, 10MB 이하)
- 업로드 진행률 표시 (0-100%)
- OCR 처리 상태 메시지 표시
- 성공 시 성공 메시지와 함께 결과 미리보기 표시
- 실패 시 오류 메시지와 실패 원인 표시

**EVENT-002**: **WHEN** 사용자가 측정 기록 목록을 조회 **THEN** 시스템은 다음을 제공해야 한다:
- 최신 순 정렬된 기록 리스트
- 페이지네이션 (페이지당 10개)
- 날짜 범위 필터링
- 로딩 상태 표시
- 빈 결과 안내 메시지

**EVENT-003**: **WHEN** 사용자가 단일 기록을 선택 **THEN** 시스템은 다음을 표시해야 한다:
- 전체 체성분 데이터 (20개 필드)
- OCR 원문 텍스트 (토글 가능)
- OCR 신뢰도 점수
- 측정 일시
- 삭제 버튼 (확인 절차 포함)

**EVENT-004**: **WHEN** 사용자가 차트 탭을 선택 **THEN** 시스템은 다음을 시각화해야 한다:
- 체중 변화 추이 (선 그래프)
- 체지방율 변화 (선 그래프)
- 골격근량 변화 (선 그래프)
- BMI 변화 (선 그래프)
- 신체 점수 변화 (막대 그래프)

**EVENT-005**: **WHEN** 사용자가 기록 삭제를 확인 **THEN** 시스템은 다음을 수행해야 한다:
- 삭제 API 호출
- 목록에서 즉시 제거
- 성공 메시지 표시
- 차트 데이터 자동 갱신

### 2.3 State-Driven Requirements (상태 기반)

**STATE-001**: **WHILE** 이미지 업로드 중 **THEN** 시스템은 다음 상태를 표시해야 한다:
- 업로드 중: 프로그레스 바 활성화, 제출 버튼 비활성화
- OCR 처리 중: 스피너 표시, "OCR 처리 중..." 메시지
- 완료: 성공 아이콘, 결과 카드 표시
- 실패: 오류 아이콘, 재시도 버튼 활성화

**STATE-002**: **WHILE** 데이터 로딩 중 **THEN** 시스템은 다음을 표시해야 한다:
- 스켈레톤 로딩 UI (목록의 경우)
- 스피너 (차트의 경우)
- 로딩 중임을 명시하는 메시지

**STATE-003**: **GIVEN** 빈 기록 목록 **WHEN** 표시될 때 **THEN** 시스템은 다음을 제공해야 한다:
- "아직 측정 기록이 없습니다" 메시지
- 첫 업로드 유도 안내
- 업로드 페이지로 이동하는 CTA 버튼

### 2.4 Unwanted Requirements (바람직하지 않은 상태)

**UNWANTED-001**: 시스템은 다음을 허용하지 않아야 한다:
- 지원되지 않는 파일 형식 업로드
- 10MB 초과 파일 업로드
- 빈 파일 업로드
- 손상된 이미지 파일 업로드

**UNWANTED-002**: 시스템은 다음을 방지해야 한다:
- 업로드 중인 사용자의 페이지 이탈
- 삭제 시 즉각적인 데이터 제거 (확인 절차 필수)
- 네트워크 오류 시 데이터 손실

**UNWANTED-003**: 시스템은 다음을 표시하지 않아야 한다:
- 기술적인 에러 메시지 (사용자 친화적 메시지로 대체)
- 빈 화면 (로딩 상태 항상 표시)
- 깨진 차트 (데이터 없음 상태 명시)

### 2.5 Optional Requirements (선택 사항)

**OPTIONAL-001**: 시스템은 다음을 지원할 수 있다:
- 다크 모드 테마
- 데이터 내보내기 (CSV/엑셀)
- 인쇄용 보고서 생성
- 데이터 비교 모드 (두 기록 선택)

**OPTIONAL-002**: 시스템은 다음을 제공할 수 있다:
- 목록 컬럼 순서 사용자 정의
- 차트 기간 사용자 정의
- 즐겨찾기 기록 표시

### 6.4 구현된 기능

**이미지 업로드**
- 드래그 앤 드롭 지원 (react-dropzone)
- 파일 형식 검증 (JPG/PNG)
- 파일 크기 제한 (10MB)
- 업로드 진행률 표시

**데이터 타입 시스템**
- TypeScript 타입 정의 (InBodyData, InBodyRecord 등)
- Zod 스키마를 통한 런타임 검증
- 경계값 검증 (체지방율 0-100%, 나이 0-150세)

**API 클라이언트**
- 이미지 업로드 API (`uploadInBodyImage`)
- 기록 조회 API (`fetchInBodyHistory`)
- 기록 삭제 API (`deleteInBodyRecord`)
- 페이지네이션 및 날짜 필터링 지원

**UI 컴포넌트**
- 대시보드 메인 레이아웃
- 업로드 섹션 (드롭존, 진행률 표시)
- 반응형 디자인 기반 구조
