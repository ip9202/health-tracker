## 개요

InBody 대시보드의 사용자 경험을 개선하기 위해 시각화 컴포넌트, 각성 요소, 게이미피케이션 기능을 추가합니다. 이를 통해 사용자가 자신의 건강 데이터를 더 직관적으로 이해하고, 지속적인 건강 관리 동기를 부여합니다.

## 배경

기존 InBody 대시보드는 데이터를 표시하는 기능에 집중되어 있어, 사용자가 자신의 건강 변화를 시각적으로 인식하거나 지속적인 동기를 부여받기에는 부족했습니다. 이를 해결하기 위해 다음과 같은 개선이 필요합니다:

1. **시각적 인식 개선**: 데이터를 직관적인 시각화로 표현
2. **변화 인식**: 전후 비교를 통해 개선 사항을 명확히 표시
3. **지속적 동기 부여**: 게이미피케이션을 통해 건강 관리 습관 형성 지원

## 요구사항 (EARS 형식)

### Ubiquitous (상시 요구사항)

**REQ-FE-005-001**: 시스템은 InBody 공식 색상 시스템(Blue/Green/Orange)을 사용하여 일관된 브랜드 아이덴티티를 유지해야 한다.

**REQ-FE-005-002**: 모든 컴포넌트는 React 19와 shadcn/ui 기반으로 개발되어야 한다.

**REQ-FE-005-003**: 모든 컴포넌트는 TypeScript 타입 안전성을 보장해야 한다.

### Event-driven (이벤트 기반 요구사항)

**REQ-FE-005-010**: WHEN 사용자가 InBody 결과를 조회하면, 시스템은 바디 타입 쉐이프(C/I/D)를 시각화해야 한다.

**REQ-FE-005-011**: WHEN 사용자가 체성분 데이터를 조회하면, 시스템은 ECW/TBW 비율을 시각화해야 한다.

**REQ-FE-005-012**: WHEN 사용자가 과거 기록을 조회하면, 시스템은 트렌드 스파크라인을 표시해야 한다.

**REQ-FE-005-013**: WHEN 사용자가 현재 데이터와 이전 데이터를 비교하면, 시스템은 변화를 하이라이트해야 한다.

**REQ-FE-005-014**: WHEN 사용자가 목표를 설정하면, 시스템은 진행률을 시각화해야 한다.

**REQ-FE-005-015**: WHEN 사용자가 연속으로 측정을 완료하면, 시스템은 스트릭 카운터를 업데이트해야 한다.

**REQ-FE-005-016**: WHEN 사용자가 마일스톤을 달성하면, 시스템은 업적 배지를 수여해야 한다.

### State-driven (상태 기반 요구사항)

**REQ-FE-005-020**: WHILE 사용자가 대시보드를 탐색하는 동안, 시스템은 요약 통계 카드를 표시해야 한다.

**REQ-FE-005-021**: WHILE 사용자가 목표를 추적하는 동안, 시스템은 목표 추적 UI를 제공해야 한다.

### Unwanted (금지 요구사항)

**REQ-FE-005-030**: 시스템은 InBody 공식 색상 시스템을 위반하는 색상을 사용해서는 안 된다.

**REQ-FE-005-031**: 컴포넌트는 타입 안전성을 compromise하는 방식으로 구현되어서는 안 된다.

### Optional (선택 요구사항)

**REQ-FE-005-040**: 시스템은 향상된 대시보드 컴포넌트를 통해 통합된 시각화를 제공할 수 있다.

## 기술 세부사항

### 의존성

- **React 19**: 최신 UI 컴포넌트 및 훅
- **shadcn/ui**: 재사용 가능한 UI 컴포넌트 라이브러리
- **Recharts**: 데이터 시각화 라이브러리
- **TypeScript**: 타입 안전성 보장
- **Tailwind CSS**: 스타일링

### 색상 시스템

InBody 공식 색상 시스템 유지:

- **Blue**: 주요 데이터, 정보성 메시지
- **Green**: 긍정적인 변화, 성취
- **Orange**: 주의, 개선 필요 영역

### 타입 안전성

모든 컴포넌트는 TypeScript 엄격 모드로 개발되었으며:

- Props 타입 정의
- 이벤트 핸들러 타입 안전성
- 데이터 검증 (Zod 스키마)
